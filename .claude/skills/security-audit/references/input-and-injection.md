# Input handling and injection

Input validation · SQL injection · Command injection · Path traversal · File upload · SSRF · XSS · Serialization

Work **sink-first**: grep for the dangerous call, then prove backwards whether untrusted input reaches it.

---

## Input validation

Check whether user-controlled input is validated *before* sensitive operations:

```text
Type validation      Length validation     Format validation
Range validation     Allowlisting          Encoding
Canonicalization     Content validation    File validation
```

Watch for dangerous assumptions — treating a cast as a security control:

```python
user_id = int(request["id"])   # prevents SQLi, does NOT prove ownership
```

Validation must be appropriate to the security boundary it protects. Denylists are weaker than allowlists; canonicalize before validating, never after.

## SQL injection

Look for:

```python
query = "SELECT * FROM users WHERE id = " + user_id
```

```python
query = f"SELECT * FROM users WHERE name = '{name}'"
```

...or any unsafe dynamic SQL. Prefer parameterization:

```python
cursor.execute(
    "SELECT * FROM users WHERE id = %s",
    (user_id,)
)
```

Check specifically:

* Raw SQL
* ORM escape hatches (`raw()`, `text()`, `$queryRaw`, `.query()`)
* Dynamic table names
* Dynamic `ORDER BY`
* Dynamic `WHERE` clauses
* Stored procedures
* SQL generated by LLMs

Identifiers (table/column/direction) cannot be parameterized — they need an allowlist.

For LLM-generated SQL, inspect whether this flow has adequate restrictions:

```text
User Input → LLM → SQL → Database
```

## Command injection

Search for:

```text
os.system()      subprocess.*     shell=True
eval()           exec()           child_process.exec
```

Determine whether user-controlled input can reach them. High risk:

```python
subprocess.run(
    f"convert {filename} output.png",
    shell=True
)
```

Prefer argument arrays (`shell=False`) plus strict validation. Note that `shell=False` still allows argument injection (a filename starting with `-`) — check for `--` separators or path prefixing.

## Path traversal

Inspect:

```text
open()            Path()             os.path.join()
send_file()       FileResponse()     zip extraction
tar extraction    archive extraction
```

Look for `../../etc/passwd` and equivalents, including encoded (`%2e%2e%2f`) and absolute-path overrides — note that `os.path.join(base, user)` returns `user` outright when `user` is absolute.

Ensure paths are:

1. Canonicalized (`realpath` / `resolve`)
2. Restricted to an intended base directory (verify the resolved path is *inside* the base)
3. Validated against traversal

Archive extraction needs the same check per entry (Zip Slip), plus symlink handling.

## File upload security

For every upload endpoint inspect:

```text
Filename validation      Extension validation    MIME validation
Magic-byte validation    File size limits        Archive bombs
Path traversal           Executable files        Image parser vulnerabilities
PDF parser risks         Temporary file handling Virus scanning
Storage isolation        Access control
```

Never trust `filename`, `Content-Type`, or extension alone — all three are attacker-controlled. Store with a generated name, serve from a non-executable location, and enforce the size limit at the streaming layer rather than after buffering.

## SSRF

Look for server-side requests with user-controlled URLs:

```python
requests.get(url)   httpx.get(url)   aiohttp   urllib   fetch()
```

Check whether an attacker can make the server reach:

```text
localhost / 127.0.0.1 / 0.0.0.0 / [::1]
private IP ranges (10/8, 172.16/12, 192.168/16, 169.254/16)
cloud metadata endpoints
internal services, Docker services, Redis, databases
```

Evaluate redirect handling too — a public URL that 302s to a private one defeats naive host allowlists, so re-validate after each hop (or disable redirects). Also check DNS rebinding exposure and non-HTTP schemes (`file://`, `gopher://`).

## XSS

Inspect:

```text
HTML rendering       Templates              React dangerouslySetInnerHTML
innerHTML            DOM manipulation       Markdown rendering
User-generated HTML
```

Determine whether untrusted content is properly escaped or sanitized, and whether auto-escaping is disabled anywhere (`|safe`, `v-html`, `{{{ }}}`).

Distinguish `Stored XSS` / `Reflected XSS` / `DOM XSS` — they differ in blast radius. Check CSP and cookie `HttpOnly` as mitigating context, not as a substitute for escaping.

## Serialization

Look for:

```text
pickle          yaml.load        unsafe deserialization
eval            marshal          custom object deserialization
```

Especially dangerous:

```python
pickle.loads(user_data)
```

This is remote code execution whenever the data crosses a trust boundary — including cache, queue, and session payloads that an attacker can influence. `yaml.safe_load` and JSON are the safe defaults.
